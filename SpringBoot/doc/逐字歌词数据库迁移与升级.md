# 逐字歌词数据库迁移与升级

此版本为 `song` 表增加可空的 `karaoke_lyrics` 列。现有逐行歌词仍保存在 `lyrics`，迁移不会改写或搬动旧歌词数据。旧服务端忽略新列仍可运行；回退应用版本时保留该列即可，避免删除用户上传的逐字歌词。

## Docker Compose 部署

在项目根目录执行下面步骤。迁移前先备份数据库；SQL 文件只运行一次。容器名按仓库的 Compose 服务名 `mysql`、数据库名 `futari` 编写。

```bash
# 1. 备份。命令会从容器环境读取 root 密码，备份文件写在当前目录。
docker compose exec -T mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers futari' > futari-before-karaoke.sql

# 2. 添加新列。把 SQL 文件通过标准输入传给 MySQL 容器。
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" futari' < SpringBoot/sql/migrations/004_song_karaoke_lyrics.sql

# 3. 确认列已存在。
docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "SHOW COLUMNS FROM futari.song LIKE '\''karaoke_lyrics'\'';"'

# 4. 替换 build/futari-server.jar 后重启后端。
docker compose up -d server
docker compose logs --tail=100 server
```

如果第 2 步报告列已存在，先用 `SHOW COLUMNS FROM futari.song LIKE 'karaoke_lyrics';` 确认上次迁移已经完成，不要再次执行 `ALTER TABLE`。若迁移出错，先保留原服务和备份，检查 MySQL 完整错误信息；该迁移使用 MySQL 8 的 `ALGORITHM=INSTANT`，不会复制歌曲数据。

## systemd / 本机 MySQL 部署

将数据库名和连接账号替换为实际值，并通过受限权限的 option file 提供密码，避免把密码写入命令历史：

```bash
mysqldump --defaults-extra-file=/etc/futari/mysql-client.cnf --single-transaction --routines --triggers futari > futari-before-karaoke.sql
mysql --defaults-extra-file=/etc/futari/mysql-client.cnf futari < SpringBoot/sql/migrations/004_song_karaoke_lyrics.sql
mysql --defaults-extra-file=/etc/futari/mysql-client.cnf -e "SHOW COLUMNS FROM futari.song LIKE 'karaoke_lyrics';"
sudo systemctl restart futari.service
sudo journalctl -u futari.service -n 100 --no-pager
```

`mysql-client.cnf` 至少应包含 `[client]`、`user`、`password` 和 `host`；文件权限设为仅数据库运维用户可读。实际 SQL 执行与服务重启由部署人员按现有维护流程完成。

## 回滚

如果新服务端启动或功能异常，回退到旧 JAR 并重启即可。旧代码会忽略 `karaoke_lyrics`，原 `lyrics` 数据不会受影响。不要在普通应用回滚时删除新列；删除列会永久丢失已上传的逐字歌词。只有明确决定丢弃所有逐字歌词并已完成备份时，才单独评估删除该列。

新建数据库直接使用当前 [`../sql/schema.sql`](../sql/schema.sql)，不需要执行此迁移。Compose 的初始化 SQL 只会作用于首次创建的数据卷；已经运行的卷必须按上面的步骤显式迁移。
