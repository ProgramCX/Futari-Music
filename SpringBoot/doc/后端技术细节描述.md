# 同步听歌系统 —— 后端技术细节描述

> 本文件保留初期设计讨论。已实现的接口、部署步骤、协议和与初稿不同的决策，以同目录的[后端实现与部署.md](后端实现与部署.md)为准；代码遵循 `.codex/rules/Futari后端AI编码规范.md`。初稿中的 Java 21/25、MinIO、springdoc 和 `com.xxx` 包名没有用于当前实现。

> 当前实现已将歌曲和专辑改为多首歌曲关联一个专辑，支持专辑列表、上传时选择/新建专辑、管理员编辑/软删除歌曲及共享专辑图片。初稿中数据库和接口示例不完整，当前字段、权限、迁移顺序以[实现文档](后端实现与部署.md)和 `sql/schema.sql` 为准。

## 1. 技术栈总览

当前歌单读取会跳过缺失或软删除歌曲，并按原歌单顺序返回有效项；排序校验使用有效歌曲集合。房间新增创建者专用 `DELETE /api/rooms/{id}`，允许创建者离房后解散，向成员发送 `ROOM_DELETED` 后清理 Redis 房间热状态与映射，不影响账号登录。详细返回码和协议见[后端实现与部署.md](后端实现与部署.md)。

| 模块 | 选型 | 说明 |
|---|---|---|
| 语言 / 框架 | Java 21（或 25）+ Spring Boot 3.x | 主框架 |
| 持久层 | MyBatis-Plus + MySQL 8 | 用户、歌曲、歌单、搭子、房间元数据 |
| 缓存 / 实时状态 | Redis 7（Spring Data Redis + Lettuce） | 有状态会话、房间热状态、邀请、在线状态 |
| 实时通信 | Spring WebSocket（原生 WS，不用 STOMP） | 播放控制广播、邀请推送、状态通知 |
| 认证 | jjwt + Redis | JWT 签名 + Redis 会话记录实现有状态登录（使用Spring Swecurity） |
| 文件存储 | MinIO+ Nginx 发文件 | SHA-256 内容寻址、X-Accel-Redirect 支持 Range |
| API 文档 | springdoc-openapi | 接口联调 |
| 构建 | Maven | |

**核心架构原则：控制流与数据流分离。** WebSocket 只传控制指令与通知（JSON，体积极小）；音乐文件走 HTTP，由 Nginx 直接发文件，不经过 Spring 读流。

## 2. 权限模型

用户表上三类权限，全部由 admin 在 Qt 客户端管理选项卡中维护：

| 字段 | 含义 | 默认值 |
|---|---|---|
| `role` | USER / ADMIN | USER |
| `can_upload` | 是否可上传音乐 | false |
| `can_manage_server_playlist` | 是否可创建/修改**服务器歌单** | false |

- 个人歌单：任何登录用户都可创建和修改**自己的**歌单，无需授权；
- 服务器歌单：仅 `role = ADMIN` **或** `can_manage_server_playlist = true` 的用户可写，所有人可读；
- 上传接口：校验 `can_upload`；
- 管理接口（`/api/admin/**`）：仅 `role = ADMIN`。

校验统一放在一个拦截器 / 自定义注解（如 `@RequirePermission("upload")`）里完成，不要在每个 Controller 里手写 if。

## 3. 数据库设计（MySQL）

```sql
-- 用户
CREATE TABLE user (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(32) UNIQUE NOT NULL,            -- 登录名
    nickname VARCHAR(32) NOT NULL,                   -- 显示名（被搜索的字段）
    avatar_url VARCHAR(255),
    password_hash VARCHAR(100) NOT NULL,             -- BCrypt
    role VARCHAR(10) NOT NULL DEFAULT 'USER',        -- USER / ADMIN
    can_upload TINYINT(1) NOT NULL DEFAULT 0,
    can_manage_server_playlist TINYINT(1) NOT NULL DEFAULT 0,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 歌曲（hash 内容寻址，全站去重）
CREATE TABLE song (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    hash CHAR(64) UNIQUE NOT NULL,                   -- SHA-256
    title VARCHAR(128) NOT NULL,
    artist VARCHAR(128),
    duration_ms INT,
    file_size BIGINT,
    format VARCHAR(10),                              -- mp3 / flac / aac ...
    uploader_id BIGINT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (uploader_id) REFERENCES user(id)
);

-- 服务器歌单（公共歌单，受权限管控）
CREATE TABLE server_playlist (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(64) NOT NULL,
    description VARCHAR(255),
    cover_url VARCHAR(255),
    creator_id BIGINT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (creator_id) REFERENCES user(id)
);

CREATE TABLE server_playlist_song (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    playlist_id BIGINT NOT NULL,
    song_id BIGINT NOT NULL,
    sort_order INT NOT NULL DEFAULT 0,
    UNIQUE KEY uk_pl_song (playlist_id, song_id),
    FOREIGN KEY (playlist_id) REFERENCES server_playlist(id),
    FOREIGN KEY (song_id) REFERENCES song(id)
);

-- 个人歌单（每人多套，自己全权管理）
CREATE TABLE user_playlist (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    name VARCHAR(64) NOT NULL,
    description VARCHAR(255),
    cover_url VARCHAR(255),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES user(id)
);

CREATE TABLE user_playlist_song (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    playlist_id BIGINT NOT NULL,
    song_id BIGINT NOT NULL,
    sort_order INT NOT NULL DEFAULT 0,
    UNIQUE KEY uk_pl_song (playlist_id, song_id),    -- 重复添加天然幂等
    FOREIGN KEY (playlist_id) REFERENCES user_playlist(id),
    FOREIGN KEY (song_id) REFERENCES song(id)
);

-- 常听搭子（单向收藏）
CREATE TABLE favorite_partner (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    partner_id BIGINT NOT NULL,
    remark VARCHAR(32),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    UNIQUE KEY uk_user_partner (user_id, partner_id),
    FOREIGN KEY (user_id) REFERENCES user(id),
    FOREIGN KEY (partner_id) REFERENCES user(id)
);

-- 房间（元数据持久化；成员与播放状态在 Redis）
CREATE TABLE room (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(64) NOT NULL,
    owner_id BIGINT NOT NULL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (owner_id) REFERENCES user(id)
);
```

要点：
- `*_playlist_song` 的 `(playlist_id, song_id)` 唯一索引让"批量添加"可以用 `INSERT IGNORE` / `ON DUPLICATE KEY UPDATE` 幂等实现，客户端重复提交不出错；
- 排序用 `sort_order`，歌单内拖拽排序时批量更新该字段。

## 4. Redis 数据结构

```
login:{userId}              → jti                    有状态会话，TTL = JWT 有效期
online:{userId}             → wsSessionId            在线状态，WS 断开即删
room:{roomId}:state         → JSON                   当前歌曲/状态/位置/服务器时间戳
room:{roomId}:members       → Set<userId>            房间成员
room:{roomId}:playlist      → List<songId>           一起听播放列表
invite:{inviteId}           → JSON                   邀请单，TTL 60 秒自动过期
user:{userId}:invites       → Set<inviteId>          某用户待处理邀请
song:meta:{songId}          → JSON（可选）           热门歌曲元数据缓存
```

房间状态 JSON 示例：

```json
{
  "currentSongId": 42,
  "status": "playing",
  "positionMs": 65300,
  "serverTimestamp": 1759412345678
}
```

## 5. 认证：JWT + Redis 有状态登录

- **登录**：校验账密 → 生成 JWT（payload：`userId`、`jti`、`role`、`exp`）→ 写 Redis `login:{userId} → jti`，TTL 与 JWT 一致；
- **鉴权**：拦截器验签 + 查 Redis 中 jti 存在且匹配，二者缺一不可；
- **登出 / 强制下线**：删 Redis 记录，JWT 立即失效；
- **权限热更新**：admin 修改权限后可直接踢用户下线（删 `login:`），用户重登即生效；
- **WebSocket 鉴权**：连接建立时 `?token=xxx`，验证通过后绑定 `userId ↔ wsSession`，写入 `online:`；
- **密码**：BCrypt 加密存储；admin 重置密码接口直接写入新 hash。

## 6. 音乐文件管理

- 上传接口（需 `can_upload`）：接收文件 → 计算 SHA-256 → 若 hash 已存在则只建元数据不重复存盘（全站去重）→ 否则写入磁盘 `{storage}/{hash}.{ext}`；
- 下载：`GET /api/songs/{hash}/file` 鉴权后下载文件。Nginx 代理设置 `X-Futari-Nginx: 1` 时由 `X-Accel-Redirect` 直接发文件；开发直连 Spring 时由 Spring 流式返回。两种路径均支持 **Range 请求**（客户端断点续传）；
- 后端不引入音频标签解析依赖；Qt 桌面客户端可使用 Qt Multimedia 读取标签并提供正则候选，服务端只校验和存储用户确认后的元数据。

### 当前实现补充：专辑实体与歌曲编辑

- `album` 表持有专辑名、专辑艺术家及共享图片；`song.album_id` 是可空外键，关联形成多对一。专辑名称可重名，唯一身份为 `(name, artist)`。旧 `song.album` 和单曲封面字段保留做兼容，迁移脚本 `002_song_albums.sql` 回填专辑，`003_album_artist_identity.sql` 增加艺术家和复合唯一索引。
- `GET /api/albums` 用于查询专辑列表；上传请求用 `albumId` 关联现有专辑，或用 `newAlbumName/newAlbumArtist` 创建/复用专辑，`albumCoverFile` 写入共享图片，`songCoverFile` 写入歌曲图片。相同音频 hash 重复上传继续返回原记录，忽略本次提交的元数据。
- `GET /api/songs/mine` 按当前登录用户的 `uploader_id` 分页返回已上传歌曲，用于 Qt 客户端的上传历史；失败的传输任务不进入此接口的成功记录。
- `PUT /api/songs/{id}` 和 `DELETE /api/songs/{id}` 仅管理员可用。更新支持可选替换音频、歌词、专辑关联与图片；修改现有专辑名称或图片会同步影响该专辑所有歌曲。删除逻辑删除歌曲记录，不删除按 hash 存储的二进制文件。
- `SongResponse` 新增 `albumId`、`albumArtist`，保持旧 `album` 字符串字段；关联专辑的 `coverUrl` 使用 `/api/albums/{id}/cover`，单曲封面路由继续兼容旧数据。直连 Spring 的歌曲文件接口处理单段 Range 并返回 206/416，供 Qt 下载队列断点续传。

## 7. 歌单系统

### 7.1 服务器歌单（公共歌单）

- 读：所有登录用户可列表、查看详情；
- 写（创建 / 改名 / 增删歌曲 / 排序 / 删除歌单）：拦截器校验 `role = ADMIN OR can_manage_server_playlist = true`；
- 典型用途：官方推荐、排行榜、主题合集。

### 7.2 个人歌单

- 每个用户可建多套，仅能操作 `user_id = 自己` 的歌单（SQL 层强制带 user_id 条件，防越权）；
- **听歌中收藏**：客户端调 `POST /api/playlists/{id}/songs { songIds: [x] }` 把当前播放歌曲加入指定歌单；
- **从一起听列表导入**：客户端在房间播放列表中勾选部分歌曲（或全选），批量提交 songIds，服务端 `INSERT IGNORE` 幂等写入并返回新增数量；
- 排序：`PUT /api/playlists/{id}/order { songIds: [...] }` 全量重排。

## 8. 房间与同步播放

### 8.1 同步模型

- 房间 = 一份共享播放状态（存 Redis）+ 一个共享播放列表；
- 控制指令只在**状态变更**时广播：PLAY / PAUSE / SEEK / NEXT / PLAYLIST_UPDATE，均携带服务器时间戳；
- 播放中不持续广播进度；由客户端各自按公式推进，服务器只做定期（10~30s）进度广播用于对时。

### 8.2 客户端校准公式（后端要提供的支撑）

- WS 层实现 PING/PONG：客户端连上后多次 ping，估算 RTT 与服务器时间偏移 `offset`；
- 客户端本地应在位置 = `positionMs + (now() + offset − serverTime)`；
- 中途进房（含接受邀请进房）：`GET /api/rooms/{id}/state` 拉一次全量状态 + 播放列表，按公式定位开播。

### 8.3 邀请系统

- `POST /api/rooms/{id}/invite { partnerId }` → 校验对方在线（查 Redis `online:`，不在线直接返回"对方不在线"）→ 生成 inviteId 写 Redis（TTL 60s，状态 PENDING）→ WS 推送 INVITE 给目标用户，消息内含邀请人、房间名、**房间当前歌曲名**（提高接受率）、成员数；
- 接受：校验未过期 → 返回房间全量状态（复用中途进房逻辑）→ 写入成员集合 → 广播 MEMBER_JOIN；
- 拒绝 / 超时：删除邀请记录即可。

## 10. WebSocket 消息协议

统一信封：`{ "type": "...", "serverTime": 1759412345678, "data": { ... } }`

| 方向 | type | data 内容 | 说明 |
|---|---|---|---|
| 上行 | PING | clientTime | 时钟校准 / 保活 |
| 下行 | PONG | echo + serverTime | 计算 RTT 与偏移 |
| 上行→广播 | PLAY | songId, positionMs | 播放（含切歌） |
| 上行→广播 | PAUSE | positionMs | 暂停 |
| 上行→广播 | SEEK | positionMs | 拖动进度 |
| 上行→广播 | NEXT | — | 下一首 |
| 上行→广播 | PLAYLIST_UPDATE | songIds[] | 一起听列表变更 |
| 下行 | SYNC | positionMs, status, serverTime | 定期对时（10~30s） |
| 下行 | MEMBER_JOIN / MEMBER_LEAVE | user 简要信息 | 成员变动 |
| 下行 | INVITE | inviteId, from, room（含当前歌曲） | 邀请推送 |
| 下行 | PARTNER_STATUS | userId, online, roomId | 搭子状态变更 |
| 下行 | KICKED | reason | 被强制下线 |

## 12. 实施顺序（后端视角）

6. admin 管理接口 + 强制下线；
7. 打磨：断线重连状态恢复、幂等兜底、接口文档。
