# Futari Music Qt 6.8 客户端实现说明

## 工程与构建

源码位于 [`../FutariMusic`](../FutariMusic)。界面由 Qt Quick/QML 组成；C++ 负责 HTTP、WebSocket、媒体播放、缓存、系统通知及状态。最低 Qt 版本 6.8，C++17，CMake 构建。Windows 上同时需要 Qt Quick、Quick Controls 2、Multimedia、Network、WebSockets、SVG 和 Widgets（仅供系统托盘通知使用）；图标由 Qt Quick Effects 按主题着色。

本机验证命令（按实际 Qt 安装目录调整）：

```powershell
$env:Path = 'D:\Qt\Tools\mingw1310_64\bin;D:\Qt\6.8.3\mingw_64\bin;' + $env:Path
& 'D:\Qt\Tools\CMake_64\bin\cmake.exe' -S Qt/FutariMusic -B Qt/FutariMusic/build-agent -G Ninja -DCMAKE_PREFIX_PATH='D:\Qt\6.8.3\mingw_64' -DCMAKE_MAKE_PROGRAM='D:\Qt\Tools\Ninja\ninja.exe' -DCMAKE_CXX_COMPILER='D:\Qt\Tools\mingw1310_64\bin\g++.exe'
& 'D:\Qt\Tools\CMake_64\bin\cmake.exe' --build Qt/FutariMusic/build-agent
& 'Qt\FutariMusic\build-agent\appFutariMusic.exe'
```

服务地址在登录页填写，默认 `http://127.0.0.1:8081/`，对应仓库 Nginx 示例端口。生产环境建议填写 Nginx 地址，音频和封面由 Nginx `X-Accel-Redirect` 直发；开发调试也可填写 Spring 地址（默认 8080），后端会鉴权后直接流式返回音频和封面。音频两种路径均支持 Range 断点续传。按 [`../../SpringBoot/doc/后端实现与部署.md`](../../SpringBoot/doc/后端实现与部署.md) 配置 Nginx、MySQL、Redis。密码不会落盘；仅在用户勾选「自动登录」时，JWT 才写入 `QSettings`，启动时通过 `GET /api/auth/me` 校验并读取最新权限。用户名、服务地址和主题也写入 `QSettings`。

参考图片存放在 [`../参考图片`](../参考图片)：五张 QQ 音乐/QQ 界面截图仅用于布局和视觉参考。界面使用 Futari 自身文案与功能，未接入 QQ 登录、会员或购买服务。可通过后端本机配置预置管理员账号；未配置时，登录页没有预置账号，首个注册账户会成为管理员，后续账户为普通用户。管理员默认拥有歌曲上传和服务器歌单管理权限，客户端按角色显示有效权限。窗口使用无系统标题栏的自绘边框、拖动标题区、窗口控制按钮和边缘缩放，登录页保持完整深色背景。复选框、角色选择器分别使用 `FutariCheckBox`、`FutariComboBox`，颜色、圆角、勾选标记和弹出列表都读取 `Theme.qml`，避免平台默认控件出现黑色文字或白色菜单。主要按钮和输入框分别复用 `FutariButton`、`FutariToolButton` 与 `FutariTextField`，使用圆角和低对比 hover/pressed/focus 状态；功能图标来自 `qml/assets/icons/*.svg`，以白色矢量蒙版绘制并由 `SvgIcon` 统一着色，图标主色/次色/强调色/禁用色均从 `Theme.qml` 读取，不用字符拼成图标。主题文件还集中管理按钮、输入框、圆角和动画时长；新增控件应引用语义令牌，不在页面内重复声明主题色。账户信息、管理员/普通用户身份、浅色/深色开关和退出登录集中在独立账户页，从主界面右上角账户图标进入。视觉上采用清晰层级、克制的绿色强调、较大交互目标和稳定空间结构；交互反馈与手动主题切换立刻生效，避免持续装饰性动画。

## 已接通的流程

1. 注册、登录、退出、可选自动登录；曲库搜索、歌曲元数据、歌手与专辑展示。单曲和批量上传都默认开启“根据元信息自动填充”“自动查找歌词”。桌面端使用 Qt Multimedia 尝试读取标题、歌手、专辑、专辑艺术家、时长、格式和嵌入封面；FLAC 另解析 Vorbis Comment、STREAMINFO 和 PICTURE block，补齐媒体后端未提供的专辑标签、时长或封面。读取结果按请求 ID 回传，手动编辑过的歌名/歌手不会被异步结果覆盖。标签缺少歌名时使用文件名，文件名正则继续提供倒序候选。歌词在音频同目录按完整同名优先找 `.lrc`、再找 `.txt`，支持常见 BOM/本地编码回退，用户仍可手动替换、移除或直接编辑歌词。
2. 上传时可选择现有专辑或明确选择新建；重复名称由名称与专辑艺术家匹配，无法唯一判断时保留为未关联状态等待用户选择。批量流程先解析并展示可编辑列表，再由用户确认后逐首加入上传队列；单个文件出错不阻塞其余歌曲。重复选择的同一路径文件会跳过并显示数量，批次创建同名新专辑时后续歌曲复用服务端专辑身份，不重复提交共享封面。
3. 曲库上传入口的下拉菜单支持单曲或批量上传。左侧「上传与下载」打开四个真实数据页签：正在上传、正在下载、上传的歌曲、下载的歌曲。上传并发为 1、下载并发为 2；任务含字节进度、速度、状态、失败原因、重试、取消和按账户持久化。成功任务隐藏进度条，取消任务立即从任务列表移除；下载取消会清理临时 `.part` 文件。下载任务将 `.part` 保存在建任务时确定的目录中，服务端支持 Range 时断点续传并在完成后校验 SHA-256；直接 Spring 和 Nginx 部署均支持 Range。上传暂无分块/断点协议，暂停会中止网络请求，继续时从头重传，界面会说明。
4. 曲库歌曲右键菜单可创建下载任务；任务完成后显示实际保存位置，可打开文件夹或调用本地播放器播放。手工删除的文件在下载记录中标记为本地文件已移除；再次请求同一首歌时重新下载。文件名过滤非法字符，已有重名文件采用编号，不覆盖。
5. 左侧底部设置页提供下载与缓存设置。下载目录默认系统 Music 目录；缓存开关、缓存目录、真实占用大小及清理都已连接到播放器缓存。下载和缓存目录重叠时拒绝保存/清理；清理仅匹配应用的 hash 缓存文件并跳过当前活动文件，不删除下载歌曲。设置存入 QSettings。顶部前进/后退按钮复用现有 `currentPage` StackLayout 导航，历史有界且相邻重复页面不会入栈。
6. 管理员可在曲库歌曲行右键打开菜单进入独立「编辑歌曲」页。页面预填服务端歌名、歌手、专辑和歌词，允许替换音频、编辑或清除歌词、切换/新建专辑、改专辑名称和更换专辑图片；更改已选专辑名称或图片时提示会影响该专辑下所有歌曲。页面底部提供红色删除操作，二次确认后软删除歌曲。普通账号不显示编辑菜单。
7. 创建/加入/离开房间，房主授予或撤销控制权；共享播放、暂停、定位、上一首、下一首与房间队列增删排序经 WebSocket 发送。客户端通过 PING/PONG 估算服务器时钟差，按 `serverTimestamp` 推算播放位置，仅在误差超过 500 毫秒时定位。
8. 搜索用户、收藏/移除搭子、向搭子发起邀请。收到邀请时显示系统通知和应用内提示；点击通知或右上角消息图标进入消息页，同意/拒绝；重连后读取待处理邀请。
9. 个人与服务器歌单分别有侧栏入口；可查看、创建、改名、删除、批量加歌、移除歌曲和调整顺序。服务器歌单写操作由管理员或 `canManageServerPlaylist` 权限控制，管理员可查看用户、调整角色和上传/服务器歌单权限、重置密码、强制下线。
10. 音频下载可使用 HTTP Range 从 `.part` 继续，完成后验证 SHA-256，再保存到应用缓存并开始播放；切歌或退出时取消旧下载，服务端错误响应不会写入断点缓存。音频缓存上限约 512 MiB，按文件时间淘汰，超过 7 天的残留 `.part` 文件会清理。封面经带鉴权的 HTTP 请求保存到本地后在歌曲行、歌词页和播放条显示，封面缓存上限约 128 MiB。歌词页解析常见 `[mm:ss.xx]` LRC 时间标签并高亮当前行，纯文本按行显示。
11. 手动切换浅色/深色主题，重启保留选择；账户页显示当前身份、提供外观开关和退出登录。主题颜色、图标主次色、控件圆角、hover/pressed/disabled 状态集中在 `Theme.qml` 与复用控件。

## 歌曲操作与弹层（2026-10-09）

- 曲库和歌单复用 `SongRow.qml`：悬停或键盘聚焦显示喜欢、下载、添加、更多四枚 SVG 按钮。封面上叠加播放按钮；操作区域预留宽度，出现按钮时歌名和专辑不跳动。
- 喜欢写入当前账号的「我喜欢」个人歌单，第一次使用时通过现有歌单接口创建；再次点击取消喜欢。加号菜单支持当前场景的默认队列、明确指定本地队列、已有个人歌单、创建新歌单并添加；有权限时也可添加到服务器歌单。
- 更多菜单包含播放、下一首播放、添加、下载、喜欢及管理员编辑歌曲。「下一首播放」把歌曲移到当前歌曲之后，并去除重复项；不会立即中断当前歌曲。新建歌单与加歌走真实 REST 请求，失败显示原因；如果歌单已建好但加歌失败，保留歌单并提示到歌单页重试。
- 弹层统一使用 `PopupSurface`、`FutariMenu`、`FutariMenuItem`、`FutariMenuSeparator`、`FutariDialog`，集中管理圆角、细边框、阴影、主题颜色、关闭按钮和短淡入淡出。单曲与批量上传以及确认弹窗共用该样式，弹层使用 `Popup.Item` 避免平台菜单边框；操作系统文件/目录选择器仍使用原生 `FileDialog`/`FolderDialog`。
- 主窗口关闭 Basic 样式的默认背景，透明窗口加 QML 抗锯齿圆角蒙版统一裁剪内容。移除整数 `QRegion` 窗口掩码；正常窗口有细描边，最大化取消圆角。SVG 素材统一采用白色蒙版，通过 `SvgIcon` 与主题语义色着色，避免 `currentColor` 被解释为黑色后无法正确着色。

## 本地与房间播放队列

| 场景 | 默认播放与加队列 | 状态来源 |
|---|---|---|
| 房间外 | 个人本地队列 | `AppController.localQueue` |
| 房间内、有控制权 | 当前房间共享队列 | 服务端房间状态与 WebSocket 广播 |
| 房间内、无控制权 | 共享播放/下一首操作禁用；默认添加到本地队列 | 共享播放跟随服务端，本地队列继续保留 |

两份队列保持独立，播放器实例全应用只有一份。创建/加入房间或接受邀请时保存个人歌曲及位置，播放器切换到房间状态；离开房间恢复个人歌曲与位置，保持暂停。房间页和底部队列面板读取同一份 `roomState.songIds`，增删排序都发送 `PLAYLIST_UPDATE`；播放器依据同一房间的 `playback` 状态播放。队列面板可切换查看本地队列，房间内本地队列只供查看，避免误改共享队列。下载历史的本地文件播放入口在房间内禁用，防止绕过共享播放控制；离开后可播放。

播放广播同步更新 `roomState.playback`，供下一首插入位置判断使用；晚到的 REST 全量状态保留时间戳更新的播放状态。异步查询歌曲信息返回时校验房间和播放状态，避免离房后旧请求重新启动共享播放。

## 当前边界与后续工作

- 音频可断点续传，但仍需完整下载并校验后开始播放；尚未实现边下边播。单首较大的文件首次播放需要等待下载完成。
- 其他格式的标签和嵌入封面读取仍取决于系统 Qt 媒体后端及文件编码；无法解析时以文件名为标题回退，仍可手工修改。FLAC 使用客户端原生标签解析兜底。批量元数据读取串行执行以限制内存和解码负载。
- 上传暂停不支持断点续传；恢复时从头传。下载断点会校验 Range 响应的偏移和最终 SHA-256，服务端不支持 Range 时从头下载。
- 上传任务恢复后若原始本地音频已移动或删除，会标记失败并要求重新选择；下载历史记录在本机，不是服务端跨设备记录。
- 曲库、房间、搭子搜索和管理员列表以每页 40 条按需加载；音频与封面缓存均有容量控制。
- 客户端 WebSocket 每 20 秒发送 PING，断线后每 3 秒尝试重连；重连后刷新邀请和当前房间状态。冷启动可选自动登录，并通过 `/api/rooms/current` 恢复仍有效的房间状态；令牌失效时需重新输入密码。
- Qt 的系统托盘通知依赖桌面环境允许通知；通知不出现时右上角消息页仍保留邀请。

## 工程约束

### 上传与歌词修复（2026-10-09）

- HTTP multipart 边界统一通过 `MultipartRequest.h` 作为带引号的参数写入。Qt 自动生成的边界含 `/` 时仍合法，单曲、批量上传及歌曲编辑共用处理。
- 「正在上传／正在下载」只显示未完成的任务，包括失败、暂停和中断的可重试任务。成功上传显示在服务端「上传的歌曲」，成功下载显示在「下载的歌曲」；取消操作移除任务，历史记录仍持久保存。
- 歌词请求由播放器切歌触发，先清空旧歌词，再按请求代次及歌曲 ID 接收响应。歌词页只展示控制器状态；离开页面、快速切歌、房间同步和本地播放都不会沿用上一首歌词。
- 批量编辑切换歌曲时暂停表单回写，提交前保存当前编辑内容，每个任务独立持有歌词快照；同目录的歌词按音频文件名主体精确匹配，不按歌手或专辑混用。
- 已删除歌曲再次上传由后端恢复原歌曲 ID，使用此次确认的信息覆盖旧元数据。还在曲库中的相同音频仍去重，重新上传不会覆盖其原歌词；需要修改时使用管理员歌曲编辑。

本次回归覆盖真实 Qt 网络传输、含 `/` 的 POST/PUT 边界、两首歌曲独立歌词匹配与编辑、上传正文隔离、歌词响应乱序及任务页筛选。指定 FLAC 文件也经过本机替身 HTTP 服务的完整传输和字节比对；服务端恢复逻辑通过单元测试验证，数据库诊断仅执行只读查询。

修复生效需要重新构建客户端并重启更新后的后端；旧客户端和运行中的旧后端不会自动加载新代码。

- QML 不直接拼接 API URL 或 JWT；网络与状态变化由 C++ 发信号通知界面。
- 需要鉴权的音频与封面使用 C++ 网络层；QML 只读取已缓存的本地封面。
- 网络调用异步执行，不阻塞 UI；应用退出时 Qt 对象树负责释放请求、WebSocket、媒体播放器与托盘对象。
- 文件路径来自 `QUrl::toLocalFile()`，缓存放在 `QStandardPaths::AppDataLocation`；主题与服务器地址通过 `QSettings` 保存。

## 验证记录（2026-10-09）

### 歌单与房间解散修复

- 个人和服务器歌单中的失效歌曲不再使整个列表返回 HTTP 404。读取时跳过已删除或缺失歌曲，原关联保留；排序校验针对当前可见的有效歌曲。客户端歌单刷新按请求代次接收，避免旧响应覆盖最新操作。
- 喜欢操作先读取服务器上的个人歌单，再复用或创建「我喜欢」，不会因本地列表尚未加载就重复创建。创建、加歌、取消喜欢及刷新均使用真实接口。
