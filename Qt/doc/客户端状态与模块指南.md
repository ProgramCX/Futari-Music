# 客户端状态与模块指南

## 从哪里阅读代码

QML 继续通过 `AppController` 的既有属性、信号和可调用方法交互。控制器实现按业务拆成多个编译单元，共用 `src/ControllerSources.cmake`，应用与回归测试使用同一份源文件清单。

| 文件 | 职责 |
| --- | --- |
| `src/AppController.cpp` | 初始化、设置、登录恢复、会话退出与变更通知 |
| `src/AppControllerLibrary.cpp` | 曲库、专辑、歌曲编辑、分页协调、歌曲索引入口 |
| `src/AppControllerRooms.cpp` | 房间进入/退出、权限与服务端房间快照 |
| `src/AppControllerPlayback.cpp` | 本地/房间播放协调、队列、歌词 |
| `src/AppControllerPlaylists.cpp` | 歌单、收藏、新建歌单并添加歌曲 |
| `src/AppControllerSocial.cpp` | 伙伴、邀请、用户搜索与管理操作 |
| `src/AppControllerCache.cpp` | 下载/缓存设置、传输入口、封面缓存 |
| `src/AppControllerSocket.cpp` | WebSocket 消息分发、邀请与时钟同步 |
| `src/CoverCompletionController.cpp` | 缺失封面读取、目录匹配、可编辑预览与顺序提交 |

这些文件仍是同一个 QML 兼容门面的实现，并非已经拆成独立业务控制器。播放器和传输管理器分别拥有自己的运行状态。

## 状态归属与生命周期

- `models/SessionState.h`：当前账号的内存快照，包括权限、房间、队列、歌单、歌曲索引及请求域。退出登录整体替换，避免遗漏新增字段。用户名、主题、自动登录偏好留在控制器及设置中。
- `models/PageState.h`：每个分页源独立拥有结果、查询词、已成功页码、总数、加载锁和请求域。刷新使旧结果集失效；成功才推进页码；失败释放加载锁，重试仍请求原页。
- `utils/RequestScope.h`：所属线程内的请求有效期。回调持有弱 token，刷新、销毁或替换状态后失效。这是响应失效机制，不会主动停止 HTTP 传输；退出会话另由 `ApiClient::abortAll` 中止请求。
- `AudioPlayer`：真实播放状态来自 `QMediaPlayer`；加载期间保留播放/定位意图。换源和停止使下载 token 失效。控制器的本地单曲查询另有请求域，避免旧详情响应覆盖新选曲或房间播放。
- `TransferManager`：任务状态和进度的唯一来源。`waiting` 进入 `uploading` / `downloading`，实际请求结果决定 `success` / `failed`。暂停保留断点，取消等待文件关闭后清理；切换账号时禁止回调启动新任务。
- QML：只保存当前标签页、抽屉开关、勾选项、待确认目标等展示状态；业务状态绑定控制器或服务。
- `CoverCompletionController`：预览和提交期间禁止重扫/改选；成功或已存在项不重复提交，失败项可重试。账号或服务器切换时清空结果并使请求 token 失效。网络请求仍统一经过 `ApiClient`。

队列拖动、共享播放模式及封面补全的操作与接口说明见[队列播放顺序与封面补全](队列播放顺序与封面补全.md)。

注销顺序是先替换会话，使身份和旧 token 失效，再停止定时器、WebSocket、播放器和网络请求，最后通知属性变化。主动中止的请求不触发业务错误回调；真实网络失败、超时和鉴权错误仍走错误通道。

## 数据入口与操作链

歌曲列表、已上传歌曲和个人/服务器歌单响应统一写入歌曲索引，单曲详情也写入同一索引。`findSong` 只做哈希查找；新增歌曲数据入口时同步调用 `cacheSongs` 或 `cachePlaylistSongs`。

房间状态中的歌曲详情也写入同一索引。兼容尚未返回歌曲详情列表的旧版服务端时，客户端按队列 ID 通过单曲详情接口补齐缺失记录；请求有并发上限，并在离开或切换房间时失效。

收藏流程按具名步骤组织：确认服务端歌单 → 必要时创建 → 添加/移除歌曲 → 刷新 → 释放操作锁。新建歌单并加歌也有独立完成入口；加歌失败仍刷新已创建的歌单，允许用户重试。

现有 QML 方法签名、服务端 API、任务持久化格式和歌曲缓存命名保持兼容。旧的多参数/布尔参数 QML 接口仍保留，后续迁移应同步修改调用方并验证，不能只改 C++ 声明。磁盘缓存仍沿用哈希命名，避免本次重构改变既有缓存数据。

## 验证

现有 `tests/playback-ui` 通过本机随机端口的 HTTP/WebSocket 替身运行实际客户端路径，覆盖播放、房间、收藏、上传下载、QML 交互及浅深主题。新增场景检查：

1. 旧分页晚返回不能覆盖新搜索，同一页在途时不重复请求。
2. 查询编码保留中文和特殊字符，失败后重试原页，成功后更新总数和游标。
3. 未缓存歌曲的晚到详情不能覆盖后续选曲。
4. 注销清空账号数据，晚到响应不能回填，也不会产生主动取消的网络错误。

配置 Qt 6.8 与匹配的 C++ 工具链后执行：

```sh
cmake -S Qt/FutariMusic/tests/playback-ui -B Qt/FutariMusic/build-playback-ui
cmake --build Qt/FutariMusic/build-playback-ui
ctest --test-dir Qt/FutariMusic/build-playback-ui --output-on-failure
```

这些测试验证本机替身服务下的行为，不代替真实服务器、多客户端或弱网联调。

房间播放以歌曲 ID、状态、基准位置和服务端时间戳识别一轮播放指令。PLAY、PAUSE、SEEK、NEXT、TRACK_ENDED 广播才控制播放器，相同指令重复通知不会再次跳转。SYNC 和播放模式通知只更新房间状态，不 seek、不恢复播放，也不按偏差改变播放速度。成员/权限等 REST 刷新不重新定位同一首歌；队列删除导致当前歌曲改变或清空时仍切歌或停止。首次入房及断线重连恢复一次服务器播放位置，重连期间漏收的指令由这次恢复处理。正常播放期间允许客户端之间出现时钟或缓冲偏差，直至下一次明确控制指令，不再定时校正。首次打开房间音频时用单调时钟补偿加载耗时；本地播放不增加这段时间。

首次加载完成后的同步保留在 `AudioPlayer` 的首次 LoadedMedia/BufferedMedia 处理内，在开始播放前执行一次：例如收到房间位置 30 秒，加载花费 3 秒，则从约 33 秒开始。加载中收到新定位会重设基准，收到暂停则停止推进基准；房间本来处于暂停状态时保持指定位置。本地模式从原指定位置开始。`m_initialMediaReady` 阻止后续缓冲状态反复触发首次定位。

媒体错误会暂停播放器、保留位置并输出歌曲 ID、错误类型和媒体状态，重复房间快照不会自动重试已失败的播放器。用户明确恢复播放时重新打开媒体。`tests/room-sync` 覆盖控制消息与周期通知的区分、指令去重、REST 刷新、重连恢复及删除当前歌曲；它不验证扬声器实际出声。


## 批量歌曲操作与播放器偏好

曲库及当前个人/服务器歌单支持按当前已加载列表选择歌曲。曲库可以批量播放、加入队列、下载；删除入口仅向管理员显示，并逐首确认和删除。歌单可以批量播放、加入队列、下载及从当前歌单移除。个人歌单不会列为自己的添加目标；服务器歌单添加/移除入口仅在账号有服务器歌单管理权限时开放。控制器仍会再次检查服务器歌单管理权限，真实权限由服务端校验。

批量删除与歌单移除保持单请求串行，避免大量选择时并发请求；最后一次响应到达后统一刷新对应列表。新建个人歌单并添加选中歌曲沿用一个有忙碌标记的异步操作链。

播放器音量由 `AudioPlayer` 持有当前值，`AppController` 在音量变化时保存到用户设置，启动时恢复。底部音量滑块旁以整数百分比展示当前值。

登录页保留居中的表单背景，去除卡片描边；注册/返回登录入口改用文字链接，支持悬停、焦点和键盘激活。
